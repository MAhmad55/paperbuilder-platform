# Phase 3 prototype adoption (2026-11-23)

The prototype was NOT adopted wholesale — it has only 2 screens (Dashboard + Approvals) against our 10, no loading/empty/error states, no search, no timeline, no audit wiring, no tests, no i18n files. Its colours and fonts are identical to ours (same Daftar tokens), so this is an adoption of details only.

1. Compact KPI cards: `.admin-kpi` min-height 88px (was 44px — the number sits on one line, so the card was mostly padding), padding 12px 14px (was 16px), and `.admin-dash__kpis` gained `align-items: start` — that was the real dead-space cause: the grid stretched every card to the tallest one (the Schools card with its status rows). Schools keeps its Active/Pending/Suspended rows, just tighter.
2. "Next in the queue" card on the dashboard: up to 3 pending approval requests (school name, city + date) each with a Review button that navigates to `/admin/approvals?selected=<id>`; the Approvals page honours `?selected` (falls back to the first filtered request when the id is missing or filtered out). Dark theme: `[data-theme='dark']` token overrides in `src/styles/tokens.css` mapping the prototype's dark values onto our token names (canvas #0C1024, paper #151A33, text #E8EAF8, muted #A9B1D0, line #2A3158, ink-700 #4B5BE0, ink-600 #6070F0, ink-100 #222A55, pen-600 #FF6B83, pen-100 #3A1822, ok #5FD3A8/okbg #12342A, warn #FFD27A/warnbg #3A2E10, danger #FF9AAA/dangerbg #3A1822), `color-scheme: dark`. Dark contrast fixes where the token flip broke readability: toast/tooltip backgrounds, destructive-button text, ghost-button colour, info/error banner text, pressed chip text, language-toggle active label, skip-link background, plain links.
